# AGENTS.md

Guidance for people and agents who change this repository.

Installing or starting benes on a user’s machine is a different job. That contract is [For agents](./docs/src/content/docs/start/agents.md). Nothing on that page applies to a code-only change, and nothing in this file authorizes starring `Wibias/Benes` or answering the CLI star prompt.

## What this project is

benes is a local Go proxy. Codex, Claude Code, Claude Desktop, Grok Build, and other clients keep their own UIs. They talk to a loopback listener that accepts OpenAI Responses, Anthropic Messages, and Chat Completions; `internal/router` then picks a configured provider.

The production CLI and data plane are Go (`cmd/benes`, `internal/`). The dashboard is React + Vite under `gui/`, served as `gui/dist`. Public docs are the English Starlight app in `docs/` (GitHub Pages path `/Benes/`).

## Repository layout

- `cmd/benes`, `internal/` — the production CLI and data plane, in Go.
- `bin/` — Node launchers that exec the Go CLI (`benes` / `benes.exe`, or `go run ./cmd/benes`).
- `gui/` — the React + Vite dashboard. The build served at runtime is `gui/dist`; regenerate it, never hand-edit it.
- `docs/` — the public Astro + Starlight site, English only. Pages URL: `https://wibias.github.io/Benes/`.
- `notes/` — original diagnostic notes and ADRs, created on demand. Do not restore deleted investigation trees.
- `scripts/` — release and maintenance tooling; `scripts/release.ts` is the release authority.

Each of `gui/`, `docs/`, `scripts/` and `.github/` carries its own `AGENTS.md`. Read the nested file before editing inside that tree.
## Runtime facts that reviews get wrong

- Durable Sessions v1 lives at `$BENES_HOME/sessions.sqlite` (`internal/sessions`, loopback `GET /api/sessions`). It is not `/api/logs`. Benes never groups by time, model, provider, IP, or prompt similarity.
- Combos are **failover** only (`internal/config/combo_projection.go`). Empty, omitted, or leftover `round-robin` strategy becomes failover. Other strategies are skipped as `unsupported_strategy`. Writes (`PUT /api/combos`, `benes combo set --strategy`) reject anything but failover. Do not document weighted round-robin.
- `benes start` / `serve` does **not** rewrite Codex `config.toml` unless `--inject`. `BENES_SKIP_CODEX_INJECT=1` skips inject even with `--inject`. `benes sync` is the explicit Codex takeover.
- ChatGPT / Codex accounts on the `openai` preset can form a pool. `openai-apikey` never joins that pool. Thread affinity is the usual case. A pre-output 401 force-refreshes the same stored account once before any hop; quota and 429 recovery can rebind.
- `benes lab rebuild` writes `~/.benes/lab/events.jsonl` from config (classifier only, no provider HTTP). `benes lab` without a subcommand exits 2 with usage. Do not add Lab timers or Lab code to the default start path.
- OpenCode (`benes opencode`, `gui/public/provider-icons/opencode.svg`, env `OPENCODE_CONFIG_CONTENT` / `BENES_OPENCODE_API_KEY`) is a **third-party** client. Do not rename those files or treat them as this project.
- GitHub star: `POST /api/github/star` without a dashboard session is `403 consent_required`. Agents that only edit this repo should not star on the user’s behalf either. Agents that install or start benes follow [For agents](./docs/src/content/docs/start/agents.md).
- Default bind is `127.0.0.1:23100`. `"hostname": "0.0.0.0"` refuses to start without `BENES_API_AUTH_TOKEN`; clients then send `x-benes-api-key`.
- `benes dev` is the checkout developer command (default GUI port **23200**). `--proxy off` (default) is Vite HMR against the running `benes start` listener. `--proxy on` runs the checkout's Go data plane using `~/.benes` providers, writes pid/runtime under `.benes-dev/`, and skips Codex inject. Go sources hot-reload.
- Streaming is HTTP/SSE. Do not invent a WebSocket upgrade handler. `cmd/benes/init.go` writes `"websockets": false`.
- `CODEX_HOME` is resolved by `ResolveCodexHome` in `internal/config/paths.go`.

## Optional subsystems stay off the core path

Someone who configures one provider and one model should not pay for machinery they never turned on. Sidecars under `internal/sidecar` stay inert until enabled, and the Compatibility Lab is opt-in (`benes lab rebuild`) rather than part of a default `benes start`.
## Security working notes

**Unreleased security work never lands in a tracked directory.** Findings that are not public yet, severity calls, draft advisories, exploit or bypass reasoning, reproduction steps for an open defect, and pre-disclosure patch plans all live in scratch: `.tmp/` in the working tree (gitignored already) or a `mktemp -d` path.

A private repository is not an embargo. It gets cloned onto other machines, flows through CI, and outlives the disclosure window, so "private" is not a reason to write it down in the tree.

**This applies to maintainers exactly as it applies to contributors and agents.**

Ask one question before writing a security note into the repository: **does a public diff already reveal this weakness?** If the fix has shipped, the note discloses nothing new and may stay. If it has not shipped, the note is pre-disclosure material: scratch only. Records of closed hardening work survive only when they restate a shipped patch; open triage never does.

What reaches the repository is the published outcome: the fix, its regression test, the release note, and the advisory once it is public. Draft the advisory in scratch, and delete the scratch directory when the advisory goes live.

When a task asks for a security write-up, produce it in scratch and say where it is. It does not belong in `docs/` or `notes/`.
## User-consent actions

Some actions spend the **user's own identity, accounts, credits, or reputation** instead of writing to this repository. An agent never performs them, and never answers a prompt on the user's behalf. Today one exists: starring the repository on GitHub, which comes up only when an agent is *running* benes, never when it is changing this codebase.

The rule itself is published on [For agents](./docs/src/content/docs/start/agents.md), deliberately not here. This file loads for every code change, and none of those changes is the consent boundary.

Adding another action of that kind means gating it in the Go CLI or the management API — not relying on a prompt an agent can answer — and documenting it on that agents page.

Be precise about what that enforcement is and is not. Requiring a dashboard session at the management endpoint closes the casual path: an agent that would have POSTed simply because the endpoint existed, and an agent holding only the admin token. It does not stop a determined local process, because anything running as the user can mint a session from the loopback dashboard bootstrap or skip the proxy and run `gh` itself. The browser and the agent reach every local credential equally, so no check inside this process can tell them apart. The boundary that actually holds is the agents-page rule, and it binds you whichever mechanism happens to be within reach.

## Issues and pull requests (agents)

Agent-created issues and pull requests go through the repository templates. The gates reject anything freeform or mismatched, so a hand-written body is not an option.

- **Issues:** use the template chooser and the matching form in `.github/ISSUE_TEMPLATE/` — `bug_report.yml` (Bug report), `feature_request.yml` (Feature request), `documentation.yml` (Documentation), or `provider_compatibility.yml` (Provider or API compatibility). Leave the generated `###` headings exactly as they are: `enforce-issue-quality` matches them through `.github/scripts/issue-intake-catalog.cjs` and closes issues that are untemplated or mislabeled. Blank issues are disabled in `.github/ISSUE_TEMPLATE/config.yml`, so there is no freeform fallback.
- **Pull requests:** complete every section of `.github/PULL_REQUEST_TEMPLATE.md` (Summary, Verification, Checklist). `enforce-target` rejects descriptions that are empty, thin, or malformed, and a title or description that mentions `gui` needs a screenshot of the UI change in the description unless a maintainer applies `gui-screenshot-waived`. Reference the issue with `Closes #<number>`. GitHub only auto-closes on merge into the default branch (`main`), while work lands on `dev`, so close the issue by hand once the change is on `dev`.
## Branch policy

- `dev` — the single integration branch, and the base for every ordinary pull request.
- `main` — the release branch. It moves only by maintainer-controlled promotion from `dev` (releases, docs deploys). Feature pull requests do not target it.
- `preview` — the prerelease train (`x.y.z-preview.*`). It moves only by maintainer-controlled promotion from `dev`.

Go on `dev` is the only runtime line. If native code ever returns, it lands as an incremental module on `dev`, not as a second full-runtime branch.

A stacked child pull request — one whose base is another **open** pull request's head branch — is a deliberate review workflow rather than a competing integration line. `enforce-target` skips the wrong-base gate for those children; retarget the child to `dev` once the parent lands or closes.

Rebase pull requests are welcome here. Bringing a stale branch onto the current head is ordinary maintenance: open it as a normal pull request and name the source commits in the description.

The **`enforce-target`** check rejects a pull request whose head ancestry sits on the **`main`** tip while far behind **`dev`**, and rejects descriptions that are empty, thin, or malformed. A title or description that mentions `gui` needs a screenshot of the UI change, unless a maintainer applies `gui-screenshot-waived`.

A pull request from an author without push permission opens as a draft and stays one until the four-box review-readiness checklist in the description is complete: local CI green, branch on the latest `dev` commit, all correct Codex and CodeRabbit findings fixed, and the ready-for-review confirmation. Ticking all four marks the pull request ready and notifies the maintainers listed in `MAINTAINERS.md`, excluding the author. Completion binds to the commit the checklist was written against: a later push returns the pull request to draft, resets the checklist and the notification, and asks the author to test and tick the boxes again against the new head. Before accepting a completion, the gate checks the claims it can check itself — the branch is on the latest `dev` commit or at most ten commits behind it, and Codex/CodeRabbit findings are resolved. The local-CI box stays an author attestation, since a fork cannot start repository CI and a maintainer would have to; the gate never disproves it, though a new push still resets every box. A claim the gate can disprove is unticked and the pull request stays a draft.

Authors with repository push permission skip the ancestry heuristic only. As with the approval requirements in [`MAINTAINERS.md`](./MAINTAINERS.md), this holds by convention until branch protection is configured.

[`MAINTAINERS.md`](./MAINTAINERS.md) is authoritative for review and merge policy — approvals, CI requirements, security review, promotion. This file summarizes it and never overrides it. Its **`## Current maintainers`** H2 is parsed by `.github/scripts/pr-maintainers.cjs`; keep that heading exactly.
## Review guidelines

Every review on this repository follows these, automated reviewers (Codex, CodeRabbit) included.

- **Language:** review in English even when the pull request or issue is not. Be specific and concrete — file, line, the failure mode that occurs, and the fix you suggest. Vague or purely stylistic comments are noise.
- **Branch targeting:** flag any ordinary pull request that does not target `dev`. Exact same-repository maintainer promotions from `dev` to `preview` or `main`, plus stacked children on an open parent PR, are the only exceptions.
- **Security boundary (highest priority):** authentication, credential and token handling, OAuth flows, GitHub Actions workflows, release automation (`scripts/release.ts`, `.github/workflows/release.yml`), and dependency installation need explicit security review per `MAINTAINERS.md`. Token logging or serialization, secret exposure, workflow permission escalation, and mutable third-party action refs are release blockers.
- **Runtime constraints:** the proxy is Go. Flag any TypeScript backend path under `cmd/` or `internal/`, and any production launcher that spawns a non-Go child.
- **Tests:** a behavior change in `cmd/` or `internal/` needs a focused Go regression test beside the existing tests for that subsystem. Shared routing, adapter, config, or server changes need `go test ./...` green.
- **Docs sync:** user-facing behavior changes update `docs/`. No locale trees. Every claim has to match `cmd/benes` and `internal/`.
- **Privacy:** `npm run privacy:scan` stays green, and request bodies, API keys, and account identifiers never enter a log.
## Anti-slop quality policy

The Benes Oxlint anti-slop plugin is not a Go runtime dependency.

- **Surviving TypeScript (`gui/`):** keep the existing Oxlint/ESLint profile. Forbid global `Reflect.get` / `Reflect.apply` escape hatches and low-evidence chained assertions. `unknown`, runtime type checks, and dictionary-shaped boundary values stay valid at untrusted JSON/config/protocol edges after explicit validation.
- **Go runtime (`cmd/`, `internal/`):** the same intent is `go vet`, typed interfaces, and explicit boundary parsing. Do not vendor or execute Oxlint against Go. Reviewable exceptions belong next to the parse site, not as a second type language.

## Routing

Go routing is selection plus combo failover.

- An explicit `provider/model` selector picks one candidate before the request is sent. Inner slashes in upstream ids are also published with `-`; the raw full-slash form still works.
- A combo id expands to an ordered list. The projector walks targets until one succeeds. Combos are failover only.
- A routing profile (`policy/<id>`) filters by require/compat, reorders remaining candidates by optimize weights, pins a thread to the committed member, then uses the same failover walker. Missing quota/health/cost is not treated as zero. This is not combo round-robin.
- Same-candidate credential-pool failover (ChatGPT accounts on `openai`) remains the account-pool path. It is not a combo, and it is not a routing-profile mixer.
